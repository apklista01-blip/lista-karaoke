5. BACKEND - SUPABASE (Banco de dados / RLS / Auth)
--------------------------------------------------------------------
Projeto: xbwipfywaksdcxwevfei (URL acima).

Tabela principal: public.songs
  - Colunas utilizadas: numero, cantor, musica, trecho, letra_completa.
  - "numero" é o identificador/único lógico (regras de negócio usam
    .eq('numero', ...)).

Tabela de recados: public.mensagens
  - id (BIGSERIAL), conteudo (TEXT), ativa (BOOLEAN),
    admin_uid (UUID → auth.users), criada_em (TIMESTAMPTZ).

Tabela de perfis: public.profiles
  - id (UUID, PK → auth.users.id), email (unique),
    is_admin (BOOLEAN default false), criado_em, atualizado_em.

Controle de admin:
  - Implementado via tabela "profiles" com flag "is_admin".
  - Trigger cria a linha em profiles automaticamente quando um novo
    usuário é registrado, marcando is_admin = true APENAS para
    sandrotattoo2222@gmail.com (admin).
  - O admin é o email: sandrotattoo2222@gmail.com

Regras de segurança (ROLE/RLS) configuradas:
  - songs:
      * SELECT: público (qualquer pessoa lê o catálogo).
      * INSERT/UPDATE/DELETE: apenas usuários autenticados que são
        ADMIN (profiles.is_admin = true).
  - mensagens:
      * SELECT: público, apenas de recados com ativa = true.
      * INSERT/UPDATE/DELETE: apenas admin.
  - profiles:
      * SELECT: apenas o próprio usuário.
      * UPDATE: apenas o próprio usuário (evita auto-marcação admin).

Autenticação:
  - Fluxo de login por email + senha (Supabase Auth).
  - Área de escrita do admin é protegida por RLS + perfil is_admin.
